# RCFM：ACDC 5% 闭环逐类别上限扰动确认实验

项目只保留一个需要在 PyCharm 中右键运行的入口：

```text
RUN_MARGIN_STAGE1.py
```

## 本轮解决的问题

上一版 PC-CBEP 已经按类别计算理论边界距离，但在真实 GPU 分类头上，1%组仍出现少量类别超过上限。根因是靠近决策边界时，解析计算与 GPU 实际卷积预测可能存在微小数值差异；小类别多翻转一个像素也会形成很大的比例误差。

新版 CL-PC-CBEP 保留原来的逐类别解析步长，再把这个步长送入真实共享分类头检查。若每个类别都满足1%上限，步长完全不变；只有实际预测超限的样本才在轻量分类头上自动二分缩小。最终复查仍失败时，该样本退回零扰动。

网络、SCB、TDCRP、伪标签损失、扰动分支权重和训练轮数均不改变。二分次数只是数值求解精度，不作为论文方法超参数；方法参数仍只有逐类别越界比例1%。

## 实验组成

固定随机种子2023。三组已经完成的旧开环逐类别 PC-CBEP 只读复用：

- `PCCBEP_001_REFERENCE`：逐类别上限1%；
- `PCCBEP_003_REFERENCE`：逐类别上限3%；
- `PCCBEP_005_REFERENCE`：逐类别上限5%。

只实际启动一次新训练：

- `CL_PCCBEP_001`：由真实分类头闭环保证每个前景类别最多越界1%。

先前已核验的完整基础为 Val Dice 89.444%、Test Dice 88.954%。对应源结果目录当前不在本副本中，因此报告会明确标为先前已核验数值，不伪装成当前目录中的结果文件。

## 运行方法

在 Linux 电脑中用 PyCharm 打开整个 `RCFM` 文件夹，选择原来的 `rcfm` Python 环境，然后右键运行：

```text
RUN_MARGIN_STAGE1.py
```

不需要命令行参数，也不需要单独运行环境检查。入口会自动验证：

- SCB 和 TDCRP 基础分支；
- 解析逐类别上限与真实分类头闭环校准；
- 小类别及相同边界距离情况下的保守处理；
- 没有可靠前景时保持原特征不变；
- 完整反向传播正常。

新训练使用独立 Python 子进程。异常退出后最多自动重试3次，并从参数完全匹配的 `last.pt` 继续。三个旧开环实验只读，旧结果不会删除或覆盖。
